# B站探店店名提取：从视频到收藏夹，中间到底错了几次？

> 关注了几十个美食探店UP主，每个视频评论区置顶都有一长串店名清单。手动逐个搜地图、逐个收藏，一个城市一下午。本仓库记录一套从B站视频自动提取店名、多维度校准、写入飞书文档的完整方法论。
>
> 本仓库是**方法论文档**，不含任何个人数据与账号信息。所有结论都来自实际跑通后的踩坑记录，文中标注了每项结论的验证方式。

---

## 它解决什么问题

美食探店UP主的视频里提到了几十家店，但店名散落在三个地方：

| 博主类型 | 店名位置 | 格式 |
|---|---|---|
| 攻略型 | 评论区置顶截图 | 备忘录/手写体清单 |
| 日常探店型 | 视频简介 | `地址：店名` |
| 标题型 | 视频标题 | `区域｜店名，描述...` |

手动看一遍视频、抄下店名、再去地图搜，一个城市要几小时，还经常打错字、搜错城市。

本仓库把整个流程自动化：**定位店名来源 → 提取/OCR → 七项校准 → 写入结构化文档**。

---

## 三种提取方式

### 方式一：评论区置顶截图（攻略型博主）

```
打开视频页 → 找置顶评论 → 下载图片 → OCR识别 → 逐家校准
```

**关键坑：** 手写体和艺术字OCR错误率很高。实测识别出的店名必须回原图逐字核对。

### 方式二：视频简介（日常探店型博主）

```
API拉视频列表 → 正则匹配"地址：店名" → 提取店名+地址
```

博主会在简介里写一行 `某区某路：店名`，直接正则提取即可。

### 方式三：视频标题（标题型博主）

```
API拉视频列表 → 按分隔符切标题 → 区域前缀+店名
```

格式是 `区域｜店名，描述...`，店名在第二个分隔符后面。

---

## 七项校准标准（每店必查）

提取出来的店名不直接用，必须过七道校验：

| # | 校验项 | 合格标准 | 不合格处理 |
|---|--------|----------|------------|
| 1 | 店名存在 | 地图搜索有精确匹配 | 回原图重新OCR，修形近字 |
| 2 | 城市匹配 | 结果所在城市=视频主题城市 | 搜出外省=识别错误，重查 |
| 3 | 类型正确 | 是餐厅/小吃，不是酒店加油站 | 类型不对=搜错了 |
| 4 | 评分正常 | 有星级评分，一般≥3分 | 无评分=可能名字错 |
| 5 | 营业状态 | 正常显示，不是灰色/歇业 | 灰色=标记歇业 |
| 6 | 地址合理 | 有详细路名/商圈 | 无地址=标记信息不全 |
| 7 | 分店全收藏 | 同名所有分店都收藏 | 只收一家=回去补 |

**实测准确率：** 约90-95%，主要错误来自手写体OCR和形近字。

---

## 几个必须踩过的坑

### 坑1：只验证前5家就标100%

批量提取后偷懒只验证前几家，就标"全部完成"。实际上后面几十家可能全错。

**修正：** 每个城市标题必须标注"应验证X家"，X必须和原始视频里的店名数量一致。

### 坑2：片区名被当成店名

标题型博主的格式是 `城市｜片区，店名`。正则写错会把"大良""杏坛"这些片区名当成店名。

**修正：** 店名在第二个分隔符后面，不在第一个。

### 坑3：跨城市探店不标城市

一个博主在多个城市探店，不标城市前缀，搜索时经常混淆。

**修正：** 店名前加城市前缀（如 `广州·xx店`、`佛山·yy店`）。

### 坑4：B站API分页重复

B站视频列表API分页有bug，翻页后返回重复数据。546条记录去重后只剩42个不同视频。

**修正：** 提取后必须按BV号去重，不能相信API返回的总数。

### 坑5：B站风控412/-799

直接curl调API会被风控。必须在浏览器登录态下fetch，且每请求间隔3-5秒。

---

## 速率限制红线

| 平台 | 安全频率 | 风控信号 | 应对 |
|---|---|---|---|
| B站API | 每请求间隔3-5秒 | 412/-352/-799 | 暂停等5分钟 |
| 百度地图 | 每店间隔2-3秒 | 滑块验证码 | 暂停10-30分钟 |
| 小红书 | 每篇间隔5秒 | 笔记加载不出 | 等10分钟 |

**通用原则：** 模拟人为操作，不要像机器一样连续快速请求。每天不超过50家。

---

## 断点续传

批量提取是长任务，必须支持中断后续跑：

```
每个城市标题格式：城市名（X家，Y%准确率）
- X = 从原视频提取的店名总数
- Y = 已校验通过的数量
- 差值 = 下次继续处理的数量
```

中断后看文档就知道从哪继续，不用从头来。

## 和下游仓库的关系

本仓库是**上游**：从B站视频提取店名并校准。

下游仓库 [map-favorites-migration](https://github.com/ninggui/map-favorites-migration) 是**下游**：把校准好的店名迁移到地图收藏夹，并解决坐标偏移问题。

```
B站视频 → [本仓库] 提取+校准店名 → 结构化文档
                                        ↓
                        [下游仓库] 批量写入地图收藏夹
                                        ↓
                              手机导航直接用
```

## 适用边界

**适用：**
- 美食探店类UP主，店名在评论区/简介/标题里
- 需要批量整理成可搜索的清单
- 愿意花时间逐家校准

**不适用：**
- Vlog类旅行博主（店名信息零散，不适合批量提取）
- 视频里没有明确店名清单的博主
- 需要精确到具体分店坐标的场景（那是下游仓库的事）
